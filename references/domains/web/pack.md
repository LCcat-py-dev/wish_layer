# 网站（web）领域包

垂直领域：做网站。选它的理由在参赛方案里是"领域与交付物同形"，脱离比赛后这个理由不成立了——现在留着它，是因为它的语料、金标签、可达集都是现成的，能拿来验证核心本身。

## 1 判域

判据：**这句话的目标是不是让某人在浏览器里完成一件事。**

| 输入 | 判定 | 说明 |
|---|---|---|
| 帮我写个 PPT | `out` | 目标不是网页 |
| 我想做个网站 | `in` | 零信息，但方向对 |
| 帮我写段代码 | 先问一句用途 | 代码可能用于网站，不得直接 `out` |
| 小红书怎么涨粉 | `out` | 不是建站能解决的，可提示一句 |
| 想做个卖东西的网站 | `in-degraded` | 是网站，但字面量级超出可达深度 |

`out` 的措辞必须是**边界陈述**，不是错误：

- 写"这个我答不了，我只懂网站怎么做"
- 不写"输入无效""超出服务范围"

同一句话，写成设计是克制，写成故障是失败（K-62）。

## 2 可达三级

| 级别 | 判定 | 响应 |
|---|---|---|
| `in` | 是网站，且在可达集内 | 正常翻译，出完整需求单 |
| `in-degraded` | 是网站，但字面描述超出可达深度 | 不拒绝。翻译到最接近的可达方案，同时输出落差说明 |
| `out` | 不是在建网站 | 边界陈述，不硬套知识库，不假装能答 |

`in-degraded` 是这个包最有价值的一级，也是唯一能证明"翻译层会反驳用户"的一级。顺从式助手没有这一级。

### 可达

- `C-01` 全部：官网、博客、文档站、机构子站、作品集、落地页、微站、导航站
- `C-02` 仅裁剪版：单页收款、商品展示页。**不含**独立站、库存、物流、售后
- `C-03` 仅小型社区：现成论坛程序能覆盖的发帖—评论—审核链路
- `R-1` `R-2` `R-3`
- 轻量形态全部：落地页、H5 活动页、导航站、作品集、微站

### 不可达

| 条目 | 理由 |
|---|---|
| `C-04` 工具应用型 / SaaS | 多租户、计费、权限属团队级投入 |
| `C-05` 服务办事型 / 政务 / 医疗 / 教育 | 触发行业许可与等保，周期以月计 |
| `R-4` 全自研 | 需团队，与目标用户画像不符 |
| `M-04` `M-05` `M-07` `M-08` `M-09` | 同上 |
| 小程序 / 快应用 / App 内嵌 | 依赖平台生态与审核，超出网站语义 |
| 多语言 i18n 架构 | 可达但收益低，默认不主动提 |

K-60：不可达条目**只能出现在 `rejected[]`**，不能出现在 `classification`。允许说明为什么不做，不允许承诺做。

K-61：用户明确要不可达的东西时，输出顺序固定——① 承认他说的是什么 ② 给出复杂度量级 ③ 给最接近的可达方案 ④ 说明差在哪。**不得跳过 ②。**

## 3 槽位表

十一格。前三格决定路线，后八格决定功能与合规。

| 槽位 | 取值 | 影响 |
|---|---|---|
| 核心任务 | 信息 / 交易 / 互动 / 工具 / 办事 | 定 `C` 类与 `R` 路线 |
| 内容维护者 | 自己 / 运营团队 / 开发 | 定要不要 CMS 与后台 |
| 技术能力 | 无 / 有前端 / 有全栈 | 定 `R-1`、`R-3`、`R-4` |
| 预算 | 低 / 中 / 高 | 定 SaaS 订阅还是自建 |
| 周期 | 天 / 周 / 月 | 定范围裁剪 |
| 部署区域 | 境内 / 境外 | 定备案与云服务 |
| 是否交易 | 是 / 否 | 定支付、订单、售后与合规 |
| 是否用户系统 | 是 / 否 | 定认证、权限与隐私设计 |
| SEO 需求 | 强 / 弱 | 定 SSG、SSR 或 SPA |
| 多语言 | 是 / 否 | 定 i18n 架构与内容工作流 |
| 合规等级 | 普通 / 等保 / 行业资质 | 定排期与成本上限 |

## 4 填充规则

| 槽位 | 能否推断 | 信号 | 提不出时 | 依据等级 |
|---|---|---|---|---|
| 核心任务 | 能，最高置信 | 动词：看 / 读 → 信息；买 / 卖 → 交易；发 / 评论 → 互动；用 / 办 → 工具或办事 | **必须发问** | 措辞推断 |
| 内容维护者 | 能 | "我自己写"→本人；"我们运营"→团队；"课题组""我们公司"→多人 | 默认本人 | 推断 |
| 技术能力 | 能，但只能定档不能定量 | 用"部署 / 域名 / 仓库"→有全栈；用"打开就能看 / 发布"→无；"我啥也不懂"→无 | 默认无 | 措辞推断 |
| 周期 | 能，出现截止词时高置信 | "下周""月底""急""开学前"→天级或周级 | 默认天级，标假设 | 措辞推断 |
| 预算 | **不能** | 几乎无语言信号；学生与个人默认零预算 | 默认最低档 | 假设 |
| 部署区域 | 半能 | 微信 / 国内支付 / 中文主体 → 境内；海外用户、英文 → 境外 | 默认境外托管（避开备案周期） | 假设 |
| 是否交易 | 能 | "卖""收款""下单""价格" | 默认否 | 措辞推断 |
| 是否用户系统 | **不能凭"要登录"判定** | 登录是手段不是目的。两种高概率真意图：不想公开（口令即可）/ 要存个人数据（才需账户） | **必须发问** | 缺口 |
| SEO 需求 | 能 | "被搜到""推广""流量""排名"→强；受众是单个已知的人→弱 | 默认弱 | 推断 |
| 多语言 | 能 | "老外""英文""海外""涉外" | 默认单语 | 推断 |
| 合规等级 | 由主类型决定，不需问 | `C-02` 触发电商法；`C-03` 触发审核与实名 | 按 `C` 类推 | 事实 |

三条硬规则（通用，核心也引用）：

- K-20：标"不能"的槽位，禁止靠模型常识补齐后当事实输出，必须降级为假设并发问
- K-21：默认值必须写进 `filled`，依据标「假设」——默认值不可见是翻译层最常见的失信方式
- K-22：依据为「措辞推断」的条目，必须同时输出触发的词；没有触发词一律降为「推断」

## 5 复杂度

> 总复杂度 ≈ 用户角色数 × 业务状态数 × 数据关系数 × 非功能要求等级

| 算例 | 估算 | 结论 |
|---|---|---|
| 官网：1 角色 × 1 状态 × 少量关系 × 低要求 | 1 人周量级 | 个人可独立完成 |
| 电商：多角色 × 多状态 × 多关系 × 高要求 | 团队数月量级 | 要产品、前后端、测试、运维 |
| SaaS：多角色 × 多状态 × 多关系 × 中高要求 | 持续迭代，没有"做完" | 要完整产品团队 |

拿到任何建站需求，先套公式估量级，再谈报价与排期。现实检验就是把这个结果和用户字面表述对比。

## 6 形容词转译

审美形容词禁止原样传递（K-55）。

| 形容词 | 转译后的可执行决策 |
|---|---|
| 高级 | 留白大；字号层级 ≤3；配色 ≤3 且低饱和；无渐变与阴影堆砌；图片质量优先；动效仅入场 |
| 简洁 | 首屏单一主行动；导航 ≤4 项；无轮播；段落短；去掉所有装饰性元素 |
| 大气 | 首屏大图或视频；标题字号大；文案字数少；不做小部件拼贴 |
| 专业 | 数据与案例优先于自述；无 emoji；克制字体；有资质页与团队页 |
| 年轻 / 活泼 | 高饱和撞色；圆角；插画替代照片；动效密度提高 |
| 温馨 | 暖色；手写体点缀；圆角；真实人物照片而非图库图 |
| 科技感 | 深色底；渐变光效；等宽字体点缀；数据可视化元素 |
| 有设计感 | 非对称布局；极端字号对比；非常规留白；打破网格 |

转译结果**必须绑定受众才生效**——"高级"在 HR、店主、设计师眼里是三套不同决策。受众未知时，转译只能作为候选，必须发问。

## 7 分类与方案

`C` / `R` / `M` 三张速查表在 `catalog.md`——出 `classification` 和 `plan` 时才需要，判域和补槽用不到。

## 8 骨架

值域是**闭的**。以下之外没有合法值：

| 类别 | 合法值 | 出处 |
|---|---|---|
| 槽位 | 十一格，值域见第 3 节 | 2.8 |
| 大类 | `C-01`–`C-05` | catalog §1 |
| 路线 | `R-1`–`R-4` | catalog §1 |
| 方案 | `M-01`–`M-11` | catalog §2 |
| 阶段 | `S-1`–`S-8` | 原知识库第 4 章 |
| 形容词 | 第 6 节那八个 | 13.4 |

出现这之外的东西 → 写进 `unmapped`，不许就近安放。

例：「做个网站，能自动读车间传感器数据并报警」——"硬件接入"在槽位和 C/R/M 里都没有位置，`unmapped` 记一条，`scope` 判 `unknown`，问人。不要因为"读数据"沾边就安进 `C-04`，那也是不可达的，两件事不一样。

## 9 降级承接的话术

`in-degraded` 的需求单必须让用户看到三个量级并列：

1. 按字面理解，这是多大量级（引用第 5 节公式）
2. 按我推断的真实意图，这是多大量级
3. 两者的差是不是用户没意识到的

三条并排摆出来，用户会立刻明白翻译层听懂的是他，不是他的字。
