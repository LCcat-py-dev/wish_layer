# 方法

判型、流程、契约，一份。领域相关的东西在 `domains/` 下，这里不写。

## 一 流程

七步，顺序不能换。第 0、1 步判错，后面全错，而且错得看不出来。

**0 判域**——这句话是不是要做出一件东西？

| 级别 | 条件 | 出口 |
|---|---|---|
| `in` | 是，且在可达集内 | 往下走 |
| `in-degraded` | 是，但字面量级超出可达深度 | 继续，落差必须说出来 |
| `unknown` | 骨架里没有能安放它的位置 | 停下问，记进收件箱 |
| `out` | 不是 | 边界陈述，不硬套，结束 |

`out` 只在两种情况下用：目标根本不是这个领域，或者用户要的是一句安慰而不是一个东西。

**1 判型**——见第二节。

**2 取事实**——从措辞里能榨的先榨，一个都不许凭空补。

| 要素 | 问什么 | 信号 |
|---|---|---|
| 核心任务 | 做出来给谁干什么 | 动词：看 / 买 / 发 / 用 / 办 |
| 受众 | 谁会用、谁会看 | "老师""客人""简历""我们组" |
| 维护者 | 以后谁更新 | "我自己写""我们运营" |
| 资源 | 能力、预算、周期 | "下周""啥也不懂""没预算" |
| 限制 | 合规、地域、既有资产 | "国内""要上线""以前那个站" |

**3 补槽**——按领域包逐格填，每格三样：值、依据、触发词。填不出来的留空，不许猜完当事实写。

**3.5 骨架核对**——每个值挂一个骨架编号（槽位 + 值域项，或 `C` / `R` / `M` / `S` 编号）。挂不上的进 `unmapped`，边界改判 `unknown`。

`unmapped` 每次都要写，空也写。它防的不是"不知道"，是**不知道自己不知道**——模型极擅长把任何说法映射到最近的类目，闭集松一点就假装对上了。

**4 现实检验**——用领域包公式算两遍：字面多大、推断多大。两行都要标依据等级。**只有字面比推断大**一个数量级以上才判 `in-degraded`；反过来是提醒，不是反驳。

**5 追问**——只问改变结论的，最多两个，一个问题只问一件事，每个自带 `why`。T4、T5 必须问，T6 不许问身份。

**6 出单**——见第三节。

**7 编译**——把需求单变成提示词：

1. 事实、措辞推断 → 硬约束
2. 假设 → "按 X 处理，不对就说"
3. `rejected` → "不要做这些"加原因
4. 未答的问题 → 并列分支，不替用户选
5. `executor_doubts` → 附末尾，说明哪里还得自己定

## 二 判型

| 编号 | 型 | 特征 | 动作 | 静默补全 | 信号 |
|---|---|---|---|---|---|
| T1 | 目的型 | 说了为什么，没说做什么 | 直接映射 | 大部分可 | "为了…""想用来…" |
| T2 | 参照型 | 指向另一个产品 | 拆 5–8 个属性，只问最改变结论的两条 | 不可 | "像…那样""类似…" |
| T3 | 形容词型 | 只有审美形容词 | 转成可执行决策，**绑受众** | 转译可，定受众不可 | "高级""简洁""大气" |
| T4 | 功能型 | 点名机制，没说目的 | 反问目的 | **禁止** | "要能登录""要能搜索" |
| T5 | 负约束型 | 只说不要什么 | 排除可以，生成不行 | **禁止** | "别太…""不要…" |
| T6 | 甩锅型 | 明确放弃表达 | 最小方案加假设写明 | 可，假设必须可见 | "你看着办""我啥也不懂" |
| T7 | 范围失控型 | 意图合理，量级荒谬 | 先现实检验，再降级 | 可，必须触发检验 | "能卖东西""像小红书" |
| T8 | 迁移改造型 | 不是新建，是改或搬 | 已有资产改阶段权重 | 可 | "搬过来""现在这个改改" |

**T4 的前提**：机制词必须是这句话里**唯一**的目的载体。"能登录的网站"→ T4；"简历上放个链接"→"简历"已经交代目的，"链接"只是手段，判 T1。

**规则**

- K-40 多型取处理成本最高者：T7 > T2 > T4 > T5 > T3 > T8 > T1 > T6
- K-41 T4、T5 永不静默补全——补错的方向看不见，用户无从纠正
- K-42 T6 禁止反问"您是什么身份"
- K-50 判型先于查表；跳过判型直接查词典，等于降级成关键词匹配
- K-54 参照物拆解必须完整进单，不能只留结论
- K-55 形容词转译必须绑定受众才生效
- K-56 判型必须写出触发它的那个词
- K-57 机制词是唯一目的载体时才判 T4

主型决定"能不能静默补"和"先做哪个动作"；副型该做的动作照做，别丢。

## 三 契约

十二个字段。

| # | 字段 | 说明 |
|---|---|---|
| 1 | `raw_input` | 用户原话，逐字，不改写 |
| 2 | `scope` | `in` / `in-degraded` / `out` / `unknown` |
| 3 | `ambiguity_type` | T1–T8，取最高成本者 |
| 4 | `classification` | 主类 + 形态 + 路线 + 方案 |
| 5 | `reference_decomposition` | T2 必填，参照物拆解 |
| 6 | `filled` | 值 + 依据 + 证据 |
| 7 | `questions` | 1–2 项 + 为什么问 |
| 8 | `rejected` | 放弃的选项 + 理由 |
| 9 | `complexity` | 字面量级 / 推断量级 / 是否触发 |
| 10 | `plan` | 裁剪后的步骤 |
| 11 | `executor_doubts` | 自己不确定、只能先猜的 |
| 12 | `unmapped` | 骨架没接住的说法，空也要写 `[]` |

**依据五级**：措辞推断 > 推断 > 假设 > 事实 > 缺口

| 等级 | 编译时怎么用 |
|---|---|
| 措辞推断 | 硬约束，必须带触发词 |
| 推断 | 硬约束，带理由 |
| 假设 | 写成"按 X 处理，不对就说" |
| 事实 | 硬约束，优先级最高 |
| 缺口 | 转成 `questions` |

没有依据的补全视同编造。分不清推断和假设时选弱的——把假设说成推断，用户就失去了推翻它的机会。

**提问三条**：`why` 必填；最多两个；不许是身份选择器（分歧必须来自措辞本身）。

**doubts 与 questions 不是一回事**：前者不阻断，继续给方案；后者阻断，等人答。字段名里的"执行方"是旧说法，实际没有第二个 Agent——补全和质疑是同一次思考的两个动作。

## 四 十条铁律

违反任意一条，输出就退化成"普通 AI 的回答"。

| # | 铁律 |
|---|---|
| R1 | 判型先于补全；没有触发词不算判型 |
| R2 | T4、T5 永不静默补全 |
| R3 | T6 禁止反问身份 |
| R4 | 每条补全标依据；措辞推断必须写出触发词 |
| R5 | 默认值必须出现在单子上，标成假设 |
| R6 | 写不出"为什么这项改变结论"的问题，不许问 |
| R7 | 审美形容词不许进单，先转译并绑受众 |
| R8 | 参照物不许整体照搬，拆维度 |
| R9 | 不可达条目只能进 `rejected[]` |
| R10 | 允许否定用户对形式的判断 |

## 五 底稿格式

用户说"展开""你怎么判的"，或者要写进评测时才摊。六块，每条破折号**先写等级，再写证据**：只有等级没证据等于没说，只有证据没等级没法打分。

```
**判型** T?（触发词：…）· 边界 in / in-degraded / out / unknown

**没对上骨架**
- 原话里的说法 —— 为什么对不上（一项都没有就写"无"）

**已确定**
- 维度：值 —— 措辞推断（触发词「…」）
- 维度：值 —— 推断（为什么这么推）
- 维度：值 —— 事实（依据）

**我猜的**（可推翻）
- 维度：值 —— 假设（为什么这么猜），要改就改这里

**要问**
1. 问题 —— 为什么问：…

**没做**
- 方案 —— 原因
```

规格单独一段，放在最后：

```
**执行规格**

（编译后的提示词，写在代码块里）
```
