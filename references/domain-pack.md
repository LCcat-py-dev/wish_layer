# 领域包规范

核心与领域的分界线：**判断怎么想**归核心，**这个领域有什么可填**归包。

换个领域要重写的只有包，核心一个字不动。如果换领域时改了 `references/` 里跟领域无关的那几份，说明有东西没放对位置。

## 一个包必须提供九样

| # | 内容 | 没有它会怎样 |
|---|---|---|
| 1 | 判域判据：什么算 `in`、什么算 `out`、典型误判 | 判域全凭模型常识，同一个领域两次判得不一样 |
| 2 | 槽位表：有哪些维度、取值、影响 | 补出来的单子每个领域各长各的 |
| 3 | 填充规则：哪些能从措辞推、信号词、默认值、依据等级 | 靠模型自由发挥补齐，依据全是编的 |
| 4 | 复杂度公式 + 算例 | 现实检验做不了，T7 降级无从触发 |
| 5 | 可达集 / 不可达集 | `in-degraded` 判不出来，等于没有反驳能力 |
| 6 | 形容词转译表 | "高级"原样进需求单，等于没翻译 |
| 7 | 路线与方案速查（可选） | `plan[]` 只能写空话 |
| 8 | 语料 + 金标签 | 改一个字都没法验证好坏 |
| 9 | 骨架：一份闭合的值域清单 | 补出来的值没法核对，`unknown` 这一档永远判不出来 |

第 7 项可选，其余八项缺一样都不成包。第 8 项最容易被跳过——它是唯一能让"改动"变成"可比较"的东西。第 9 项最容易做假——写一份宽到能装下一切的清单，等于没有。

## 包不该出现的东西

比赛规则、排期、界面、部署、密钥、限流。这些属于某次交付，不属于领域知识。混进来之后，模型会以为要产出的是一个网页。

## 把一份现成文档改造成包

现有知识库成包的过程是这样，顺序别反：

1. 先把能跨领域讲的段落抽走，进 `references/`（原第 13、14 章、2.9 节）
2. 剩下的按上面八项分堆
3. 凑不齐八项的，说明它还不是包，只是一份资料
4. 最后把所有指向原文的交叉引用改掉——原文档的章节号和实际章节错位了一位，照抄会把执行流程导到错的地方

清单：

- [x] 判域判据（原 14.4）
- [x] 槽位表（原 2.8）
- [x] 填充规则（原 2.9）
- [x] 复杂度公式（原 6.5）
- [x] 可达集（原 14.3）
- [x] 形容词转译（原 13.4）
- [x] 路线与方案速查（原 3.1、5）
- [x] 语料与金标签（原 KB-WISH-001）
- [ ] 兜底词典的可信度标定（原 13.5，未做）

## 第二个包怎么选

判据只有一条：**这个领域的"说不清"跟网站不是同一种**。

如果只是把网站换个名字，说明核心那套 T1–T8 还没被真正检验过，加包只会掩盖问题。反过来说，新领域里如果 T1–T8 一个都套不上，那才是真有价值的发现——它意味着模糊类型本身有漏，得回头补核心。
